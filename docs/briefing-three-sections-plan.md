# 브리핑 세 영역 정리

목적: 브리핑 첫 화면의 독립 영역을 AI 통합브리핑, 프로젝트 브리핑, 스프린트별 업무현황 세 개로 제한한다.

성공 조건:
- 세 영역이 같은 레벨과 순서로 표시된다.
- 프로젝트를 선택하면 해당 프로젝트의 현재 진행 요약과 다음 행동만 기본 노출되고, 추가 근거는 접어서 확인한다.
- AI 결정 요청과 위험은 AI 영역 안에서 접근 가능하며 실패·미분석을 정상으로 표시하지 않는다.
- 스프린트 선택과 프로젝트·팀·담당자 필터가 지표와 상세 목록에 동일하게 적용된다. 스프린트 별칭 및 소수 스프린트를 지원한다.
- 진행 중 프로젝트·진행 중 작업·기한 초과·가이드 위반·진행 준비의 다섯 상세 조회와 복사를 유지한다.
- 데이터 신뢰·관리 병목·전일 변화·확인 후보를 별도의 최상위 카드로 반복하지 않는다.

작업 순서: 기존 동작 테스트 실행 → 세 영역 계약 및 필터 테스트 추가 → presenter 중복 구조 제거와 기존 상세 렌더러 재사용 → 앱 선택 이벤트 연결 → 단위 검사·문법 검사·브라우저 검증.

집계는 기존 briefingDetailItems를 재사용하고, 진행 준비는 수집 시점의 progressSetupItems를 그대로 필터링하여 상위 작업과 중복 판정을 보존한다. 실제 데이터 수집 없이 샘플 화면으로 검증한다.

## 검증 결과

- 변경 전 기존 presenter/view-model 테스트 48개 통과 확인.
- 변경 후 전체 테스트 250개 통과. 마지막 상세 필터 중복 적용 수정 후 관련 검사 38개 재통과.
- npm run build 및 신규 scope/demo 모듈 문법 검사 통과. lint/typecheck 전용 명령은 프로젝트에 없음.
- 브라우저 DOM에서 최상위 영역을 정확히 세 개로 확인: AI 통합브리핑 → 프로젝트 브리핑 → 스프린트별 업무현황.
- 프로젝트 선택 후 다른 프로젝트 요약이 중복 노출되지 않는 것을 확인.
- 스프린트 3.5 단독 선택 시 진행 중 2개, 60 추가 선택 시 5개와 상세 5개 일치.
- 스프린트60/sprint60 별칭을 하나로 표시. 검색해 60을 선택해도 기존 3.5 선택 보존.
- 가이드 위반·진행 준비 모두 상위 작업 1개 상세 보존. 개발팀 필터 후 0개, 초기화 후 1개 복귀.
- 모바일 390px에서 가로 넘침 없음. 체크박스 18×18px, 항목 최소 44px. 최초 시각 검사에서 발견된 모바일 label의 세로 배치를 수정하고 가로 정렬·중앙선 일치 재확인.
- 데스크톱 뷰포트로 복원하고 샘플 브리핑 탭을 열어 둠.
- 검증 데이터는 로컬 샘플이다. 최신 Notion 수집이나 원격 배포 검증은 수행하지 않았다.

변경 파일: public/dashboard-presenters.js(세 영역 구성), public/app.js(선택·검색·필터 이벤트), public/briefing-scope.js(기존 판정 목록 범위 조회), public/style.css(통일된 섹션과 모바일 선택기), public/dashboard-demo.js(검증 가능한 예시), test/briefing-scope.test.mjs, test/dashboard-presenters.test.mjs, test/dashboard-feature-contract.test.mjs.

제거/단순화: 별도 관리 병목 카드, 중복 프로젝트 최신 상태 목록과 그 전용 렌더러를 제거. 데이터 신뢰·변경 이력·확인 후보는 AI 근거 접힘 영역으로 통합. 프로젝트 상세는 한 개를 선택하고 현재 진행 요약·다음 행동을 기본 표시. 기존 규칙을 다시 만들지 않고 briefingDetailItems의 판정 목록을 공유.
