# 스프린트별 업무 현황

## 적용 범위

브리핑은 `1. 에이전트 통합 분석 → 2. 어제와 달라진 것 → 3. 스프린트별 업무 현황` 순서다. GPT Agent 설정·스킬·기존 agent-package 파일은 이 코드 변경으로 수정하지 않는다.

현재 스프린트는 프로젝트별 설정이 아니라 모든 프로젝트가 공유하는 하나의 운영 기준이다. 대시보드 필터 영역의 `현재 스프린트` 입력창에 숫자만 쉼표로 입력한다.

- `3` → `Sprint3`
- `3,4,5` → `Sprint3`, `Sprint4`, `Sprint5`
- `전체` → 스프린트가 지정된 모든 작업항목
- 빈칸 → 미설정. 전체로 해석하지 않으며 스프린트 기준 KPI는 미계산으로 표시

공백과 중복 숫자는 정규화한다. `3,5`는 Sprint3·Sprint5만 선택하며 Sprint4를 자동 포함하지 않는다. 기존 데이터에 Sprint5가 없어도 `5`를 직접 입력·저장할 수 있다.

입력값 변경은 먼저 조회 미리보기로 적용되고, `저장`과 관리자 인증을 거쳐야 팀 공통 운영 기준과 다음 규칙 입력에 반영된다. 프로젝트·팀·담당자는 화면 조회 필터이며 공용 현재 스프린트 설정 자체를 변경하지 않는다.

## 다섯 지표

공통 범위는 공용 현재 스프린트에 속한 활성 하위 작업항목이다. 스프린트 미사용 프로젝트는 선택값이 설정된 경우 활성 하위 작업 전체를 포함한다. 완료·일시 정지·정지·중단 항목과 비활성 상위항목 아래 작업은 제외한다.

| 지표 | 정의 |
|---|---|
| 진행 중 프로젝트 | 공통 범위에 활성 작업항목이 하나 이상 있는 프로젝트 수 |
| 진행 중 작업항목 | 공통 범위에서 상태가 정확히 `진행 중`인 항목 수 |
| 기한 초과 작업항목 | 공통 범위에서 원본 `OVERDUE` 또는 양의 초과 일수가 있는 항목 수 |
| 가이드 위반 작업항목 | 공통 범위에 가이드 위반이 하나 이상 있고 기한 초과는 아닌 항목 수 |
| 진행 준비 필요 항목 | 선택된 현재 스프린트에서 `시작 전`이며 기한 초과가 아닌 항목 수. 스프린트 미사용 프로젝트에는 적용하지 않음 |

진행 중은 상태 지표라 기한 초과와 겹칠 수 있다. 다섯 숫자를 더해 전체 업무 수로 사용하지 않는다. 기한 초과는 가이드 위반·준비보다 대표 노출을 우선하지만 상세 이슈는 삭제하지 않는다. 상위 작업 관리 문제는 기존 확인필요·감사 데이터에 남는다.

선택 밖 기한 초과와 스프린트 판정 불가·미지정 항목은 별도 진입점으로 표시한다. 보기 범위에서 제외됐다고 해결된 것이 아니다. `전체`도 스프린트 미지정 작업을 정상 스프린트 작업으로 간주하지 않는다.

## 저장과 이전

서버 환경변수 `SPRINT_SETTINGS_TOKEN`에 최소 24자 이상의 무작위 관리자 키를 설정한다. Cron 토큰과 다른 값을 사용한다. 브라우저는 입력한 키를 영속 저장소나 공유 링크에 보관하지 않는다. 키가 없으면 저장은 차단되지만 조회 미리보기는 가능하다.

설정은 기존 Notion 업무현황 요약 DB에 `sprint-settings:` 접두어의 append-only 전역 기록으로 저장한다. 프로젝트 리스트 속성과 원본 업무를 수정하지 않는다. 전역 설정이 없을 때 기존 프로젝트별 `현재 스프린트` 값이 모든 스프린트 사용 프로젝트에서 동일한 경우에만 임시 마이그레이션 기준으로 사용한다. 프로젝트별 값이 서로 다르면 자동 합치지 않고 `미설정`으로 처리한다.

전역 설정을 한 번 저장한 뒤에는 대시보드 설정을 우선한다. 빈칸 저장도 명시적인 `미설정` 기록이다. `전체`는 별도 모드로 저장하며 수집 시점에 실제 데이터에서 확인되는 모든 스프린트 값을 규칙 입력의 공용 `currentSprints`로 확장한다.

배포 후 최초 재수집과 공용 설정 저장, 다른 브라우저 재조회, 규칙 입력·GPT 분석 일치 검증을 끝낸 뒤에만 Notion의 기존 프로젝트별 현재 스프린트 속성을 숨기거나 제거한다. 이 PR은 해당 속성을 삭제하지 않는다.

저장 요청은 인증·동일 출처·입력 형식·예상 버전을 검사하고 저장 후 재조회한다. 버전 충돌을 대부분 감지하지만 Notion은 트랜잭션 CAS 저장소가 아니므로 완전히 동시인 요청을 원자적으로 잠그지는 않는다. 현재 이력은 변경 시각과 전후 입력값이며 개인별 로그인 감사 추적은 포함하지 않는다.

## 분석과의 계약

수집기는 저장된 전역 설정을 모든 스프린트 사용 프로젝트에 동일하게 주입한 뒤 기존 규칙 검증을 실행한다. `MOLIP_AGENT_INPUT_V1`의 각 프로젝트 `currentSprints`와 `sprintRelation`은 같은 전역 기준에서 만들어진다.

원본 `rules.metrics`·감사 행은 유지한다. 브리핑용 집계는 같은 공유 정책 함수로 계산하여 `rules.briefingMetrics`, 집계 단위와 공용 스프린트 기준은 `rules.briefingScope`로 별도 제공한다. `briefingScope`에는 mode, input, sprints, 설정 revision, policyVersion이 포함된다.

스프린트 조회 미리보기만으로 AI를 재실행하지 않는다. 공용 설정 저장 뒤 재수집을 요청하고, 새 규칙 입력 게시 뒤 GPT Agent를 별도 실행해야 한다. 설정이 다르거나 분석 시각이 입력보다 오래됐으면 이전 분석에 갱신 필요를 표시한다. 스프린트 설정 변경으로 숫자가 달라진 것은 업무 진척 자체가 아니다.

전체 활성 `specCatalog` 분석과 실제 병목 감지는 화면 필터로 줄이지 않는다. 실행문은 현재 Agent Instructions를 최우선으로 참조하되, 공용 현재 스프린트 판단은 당일 `MOLIP_AGENT_INPUT_V1`의 `rules.briefingScope`와 프로젝트별로 동일하게 주입된 `currentSprints`만 사용한다. 과거 프로젝트별 설정을 다시 조합하거나 추정하지 않는다.

## 검증

단위·회귀 테스트는 `npm test`, 빌드 설정의 구문 검사는 `npm run build`로 실행한다. 브라우저 검증 스크립트는 `tools/sprint-browser-smoke.py`이며 합성 데이터와 모의 저장 응답만 사용한다.

브라우저 검증은 공용 입력 `3,4`, 빈칸, `전체`, KPI/상세 목록 일치, 기한 초과 대표 우선, 전역 저장 payload, 저장 후 재수집 요청, 이전 분석 stale 표시, 관리자 키 미저장, 공유 링크 복원, 모바일 가로 넘침과 JavaScript 오류를 확인한다.

실제 운영 Notion 쓰기·자동 수집·GPT 실행·프로덕션 배포는 별도 운영 검증이 필요하다. 기존 웹 UI/일반 API의 접근 정책은 바꾸지 않았으므로 민감한 업무 데이터에 대한 배포 접근 보호도 별도로 확인해야 한다.
